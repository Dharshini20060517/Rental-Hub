     1→     1→# RentalHub – Equipment Rental Platform (Worklog)
     2→     2→
     3→     3→## Project Status Assessment (Initial)
     4→     4→
     5→     5→This is the **RentalHub** equipment rental platform. The original spec prescribed a MERN/Vite stack
     6→     6→(Express + MongoDB + Vite + Redux). This sandbox is a **fixed Next.js 16 + TypeScript + Prisma (SQLite)
     7→     7→+ shadcn/ui** environment with a single user-visible route (`/`). The build is therefore **adapted** to the
     8→     8→Next.js stack while preserving all Phase 1 functional requirements (auth + roles, equipment CRUD,
     9→     9→search/filter/compare/wishlist, owner listing management, admin oversight, audit logs, seed data,
    10→    10→file uploads, role-guarded SPA).
    11→    11→
    12→    12→## Tech Stack (Adapted)
    13→    13→- Next.js 16 App Router + TypeScript 5 (single `/` route SPA, API routes under `/api/v1/*`)
    14→    14→- Prisma ORM + SQLite (adapted from MongoDB/Mongoose) — soft delete + timestamps + indexes
    15→    15→- NextAuth-style JWT in httpOnly cookies + bcrypt (adapted from Express JWT)
    16→    16→- shadcn/ui (New York) + Tailwind CSS 4 + next-themes dark mode + Framer Motion
    17→    17→- Zustand (client state) + TanStack Query (server state) — adapted from Redux Toolkit
    18→    18→- Axios with 401 → refresh → retry interceptor
    19→    19→- Local file uploads (type/size validation, Cloudinary-pluggable) — adapted from Multer+Cloudinary
    20→    20→- Zod validation, rate limiting, audit logs
    21→    21→- Docs under `/docs` (API_CONTRACT, DECISIONS, PROGRESS, ER, AGGREGATIONS)
    22→    22→
    23→    23→## Current Goals / Completed
    24→    24→(none yet — Phase 1 build in progress)
    25→    25→
    26→    26→## Unresolved Issues / Risks / Next-Phase Priorities
    27→    27→- SQLite lacks native 2dsphere geo + full-text indexes → distance filter computed via Haversine in JS;
    28→    28→  keyword search via Prisma `contains` (LIKE). Documented in DECISIONS.md.
    29→    29→- No external Cloudinary creds → local upload storage with Cloudinary-pluggable interface.
    30→    30→- Payments simulated (Phase 2+); bookings engine (Phase 2); AI scoring/QR (Phase 3-4).
